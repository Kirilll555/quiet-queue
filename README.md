# Тихая очередь (Quiet Queue)

## Первый запуск

Команды указаны для Windows PowerShell и macOS Terminal. Git-команды на обеих системах одинаковые, отличается только запуск Python внутри виртуального окружения.

### 1. Получение проекта

```bash
git clone --branch frontend https://github.com/Kirilll555/quiet-queue.git
cd quiet-queue
```

Если репозиторий уже есть на компьютере, повторно клонировать его не нужно.

### 2. Виртуальное окружение

Windows (PowerShell):

```powershell
py -m venv .venv
```

macOS (Terminal):

```bash
python3 -m venv .venv
```

В macOS команда запуска Python — `python3`, без «3» интерпретатора в свежих версиях системы нет.

Активация окружения не обязательна: следующие команды используют его Python напрямую.

### 3. Установка зависимостей

Windows:

```powershell
.\.venv\Scripts\python.exe -m pip install --upgrade pip
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

macOS:

```bash
./.venv/bin/python -m pip install --upgrade pip
./.venv/bin/python -m pip install -r requirements.txt
```

### 4. Подготовка базы

Windows:

```powershell
.\.venv\Scripts\python.exe manage.py migrate
.\.venv\Scripts\python.exe manage.py check
.\.venv\Scripts\python.exe manage.py seed_data
```

macOS:

```bash
./.venv/bin/python manage.py migrate
./.venv/bin/python manage.py check
./.venv/bin/python manage.py seed_data
```

Миграции создают структуру базы. Команда `seed_data` заполняет демо-данные: пять учебных учреждений с кабинетами и историю оценок за последние 42 дня. Внимание: при каждом запуске она полностью удаляет старые учреждения и отметки, включая отправленные вручную. Используйте её только на учебной базе.

### 5. Установка Ollama и модели ИИ

Установите Ollama с [ollama.com/download](https://ollama.com/download), стандартный установщик (Windows — exe-файл, macOS — перенесите приложение в Applications и один раз запустите вручную, дальше оно стартует само).

В любой системе:

```bash
ollama pull qwen2.5:3b
ollama list
```

Модель весит около 1,9 ГБ. Вывод `ollama list` должен показывать `qwen2.5:3b`.

Имя модели жёстко прописано в `pages/services.py` (`OLLAMA_MODEL`). Не меняйте его без согласования с командой: у всех должна быть одна модель, иначе у части разработчиков советы ИИ молча перестанут появляться.

### 6. Настройка Яндекс Карт

Получите ключ JavaScript API в кабинете разработчика Яндекс.

Windows — в том же PowerShell, где будет запущен сервер:

```powershell
$env:YANDEX_MAPS_API_KEY = "ВАШ_КЛЮЧ"
```

macOS:

```bash
export YANDEX_MAPS_API_KEY="ВАШ_КЛЮЧ"
```

Ключ не следует записывать в исходный код или коммитить в репозиторий. Настройка действует только в текущем окне терминала: после его закрытия её нужно задать заново. При размещении сервиса переменную окружения настраивает DevOps.

Карта требует подключения к интернету. При отсутствии ключа список учреждений остаётся доступным.

### 7. Запуск

Ollama после установки работает как фоновая служба и запускается сам. Если советы ИИ не появляются, выполните во втором окне терминала:

```bash
ollama serve
```

Затем запустите сервер.

Windows:

```powershell
.\.venv\Scripts\python.exe manage.py runserver
```

macOS:

```bash
./.venv/bin/python manage.py runserver
```

Сайт: http://127.0.0.1:8000/

Оставляйте терминал открытым, пока работаете с сайтом. Остановка сервера — Ctrl+C.

`runserver` предназначен для локальной разработки. Публичное размещение настраивается отдельно.

## Повторный запуск после выключения компьютера

Перейдите в свою папку репозитория, задайте ключ карт и запустите сервер — теми же командами из шагов 6 и 7.

Если получили изменения команды с новыми миграциями, перед запуском выполните `manage.py migrate`.

## Администратор и модерация

Создайте локального администратора:

Windows:

```powershell
.\.venv\Scripts\python.exe manage.py createsuperuser
```

macOS:

```bash
./.venv/bin/python manage.py createsuperuser
```

Админка: http://127.0.0.1:8000/admin/

Через админку можно:

- создавать учреждения с адресами, часами работы и координатами;
- добавлять кабинеты и связывать их с учреждениями;
- просматривать отметки;
- одобрять заявки действием «Одобрить выбранные заявки и добавить на сайт».

Учреждение без обеих координат отображается только списком, без карты. Для демо-данных используйте явно обозначенные учебные названия и условные координаты.

## Аккаунты и отметки

Для регистрации запрашиваются ник и пароль с подтверждением. Отправка отметки требует авторизации: один аккаунт может оценивать одну очередь не чаще раза в 15 минут, общая очередь и каждый кабинет учитываются отдельно.

## Советы от ИИ (Ollama)

После расчёта прогноза сервис показывает текстовую рекомендацию от модели `qwen2.5:3b`, работающей локально: запросы и статистика не покидают компьютер.

- Первый совет после запуска сервера занимает 10–30 секунд — модель загружается в память. Последующие ответы быстрые.
- При недоступности Ollama или отсутствии модели совет просто не показывается, остальная страница работает как обычно.

## Работа с Git

Frontend-разработка ведётся в ветке `frontend`. Завершённые этапы интегрируются в `development`. Изменения команды получаем из `development`.

Перед объединением изменений сохраните свою работу коммитом и выполните `git fetch origin`.

Не используйте принудительный push в общую ветку.

Миграции включаются в коммиты. Локальная база, виртуальное окружение, файлы `.env` и ключи API в репозиторий не отправляются.

Уже применённые миграции не переписываются: изменения структуры оформляются новыми миграциями.

## Проверки и работа QA

Проверка конфигурации:

Windows:

```powershell
.\.venv\Scripts\python.exe manage.py check
```

macOS:

```bash
./.venv/bin/python manage.py check
```

Тесты QA находятся в `tests/`. Для полного прогона в подготовленном окружении:

Windows:

```powershell
.\.venv\Scripts\python.exe -m pytest -q -s
```

macOS:

```bash
./.venv/bin/python -m pytest -q -s
```

Зависимости проекта устанавливаются из `requirements.txt`, инструменты QA — из `requirements-test.txt`. Workflow выполняет установку в этом порядке, чтобы тесты проверяли командную версию Django.

Установка зависимостей, настройка браузера и команды демонстрации приведены в [плане тестирования](TEST_PLAN.md). Результаты последнего проверенного запуска — в [отчёте QA](TEST_REPORT.md). Подробный разбор проверок и ограничений измерений — в [аудите качества тестов](TEST_AUDIT.md).

## Если что-то не работает

- **Сайт не открывается, `ERR_CONNECTION_REFUSED`** — локальный сервер не запущен или завершился с ошибкой. Проверьте терминал с `runserver`.
- **Ошибка `no such table`** — выполните `manage.py showmigrations pages` и `manage.py migrate`. Если миграции считаются применёнными, а таблицы нет, сохраните резервную копию базы и разберите расхождение с backend. Не удаляйте базу и не применяйте `--fake` вслепую.
- **Все интервалы прогноза «Недостаточно данных»** — выполните `manage.py seed_data` и обновите страницу (F5). Демо-история рассчитана на 42 дня: при меньшем окне порог «3 даты и 5 оценок» недостижим.
- **Совета ИИ нет, прогноз работает** — проверьте по порядку: `ollama list` показывает `qwen2.5:3b`; служба Ollama запущена (иконка в трее или `ollama serve` во втором окне); быстрый тест `curl http://localhost:11434/api/tags` возвращает JSON.
- **Порт 8000 занят** — закройте другие окна с `runserver`.
- **Новые стили не появились** — сохраните файл и обновите страницу через Ctrl+F5 (на Mac — Cmd+Shift+R).
