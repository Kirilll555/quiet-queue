# План тестирования «Тихой очереди»

Рабочая ветка QA — `qa`. Цель приёмки — проверить путь от поиска учреждения до отправки отметки, расчёт текущей и исторической загруженности, а также публикацию предложенного учреждения. За основу взяты README, маршруты Django, шаблоны и фактический код приложения.

## Изоляция и критерии

`tests/settings.py` задаёт пустой ключ карты, ускоренный хешер паролей и пути SQLite в уникальном временном каталоге запуска. Путь тестовой базы известен до старта HTTP-сервера. Каждый поток сервера открывает собственное соединение. pytest-django применяет миграции и изолирует примеры. Браузер и нагрузка работают через временный сервер на loopback. Playwright разрешает запросы страницы к этому серверу, отвечает на запрос SDK из памяти и блокирует прочие адреса. Для прогноза и ограничения повторов фикстура времени исключает зависимость от часа запуска.

Критерии прогона — отсутствие неожиданных падений, ошибок подготовки и неожиданно прошедших известных дефектов. Для покрытия измеряются строки и ветвления пакетов pages, config и manage.py, включая миграции. Исключён каталог старых тестовых заготовок. Цель — 100% при содержательных проверках. Порог производительности команда не задавала. Фиксируются число корректных ответов, время серии, запросы в секунду и p95.

## Установка и демонстрация

Из корня репозитория, используя существующее окружение:

```sh
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python -m pip install -r requirements-test.txt
.venv/bin/python -m playwright install chromium
.venv/bin/python -m pytest --collect-only -q --no-cov
.venv/bin/python -m pytest -q -s
```

На macOS с Google Chrome в /Applications тесты автоматически используют его, установку Chromium можно пропустить. Для явного выбора установленного Chrome задайте переменную окружения `QA_BROWSER_CHANNEL=chrome`. Для поставляемого Playwright Chromium задайте пустое значение. В PowerShell замените `.venv/bin/python` на `.\.venv\Scripts\python.exe`. Runtime-зависимости берутся только из командного requirements.txt, QA-файл содержит инструменты тестирования. Локальный `.venv` содержит Django 6.1.3, командный файл фиксирует 6.1.1.

| Что показать преподавателю | Команда |
|---|---|
| Серверные проверки без запуска браузера и открытия порта | `.venv/bin/python -m pytest -m "not e2e and not load" --no-cov -q` |
| Граница повторной оценки | `.venv/bin/python -m pytest -k legacy_cooldown -v --no-cov` |
| Все браузерные сценарии | `.venv/bin/python -m pytest -m e2e -v --no-cov` |
| Нагрузка с метриками | `.venv/bin/python -m pytest -m load -s -q --no-cov` |
| Открытые дефекты как обычные падения | `.venv/bin/python -m pytest -m xfail --runxfail --tb=short --no-cov` |
| Весь набор и свежий HTML | `.venv/bin/python -m pytest -q -s`, затем открыть `htmlcov/index.html` |

Последняя команда полного прогона обновляет HTML. Отдельные демонстрации используют `--no-cov`, чтобы сохранить отчёт полного запуска. Команда с `--runxfail` возвращает ненулевой код, пока дефекты воспроизводятся.

## Служебные файлы

`pytest.ini` задаёт сбор тестов и маркеры. `.coveragerc` определяет область измерения. `tests/__init__.py` делает тестовые настройки импортируемыми. `tests/conftest.py` создаёт пользователя, клиента с сессией, учреждение, кабинет, историю и фиксированное время. Назначение каждого тестового модуля приведено в матрице. Проверки отдельных функций и входные данные сведены в TEST_CASES.md.

## Измерение JavaScript и GitHub Actions

Для локального измерения выполните следующую команду из корня проекта:

```sh
QA_JS_COVERAGE=1 .venv/bin/python -m pytest -q -s --cov-report=xml:qa-results/python.xml
```

В PowerShell сначала установите `$env:QA_JS_COVERAGE="1"`. При включённой опции tests/js_coverage.py собирает диапазоны функций V8 через Chromium DevTools Protocol, учитывает только локальные static/js и объединяет вызовы по смещениям функции по всем выполненным сценариям. Каждая сессия измерения перезаписывает qa-results/javascript.json. При запуске подмножества тестов результат относится только к этому подмножеству.

Workflow .github/workflows/qa.yml запускается на push в qa, при pull request в qa, development и main, а также поддерживает ручной запуск. Использованы тот же Python 3.14 и семейства checkout/setup-python, что в командной конфигурации ci.yml из локальной ссылки origin/devops-ci-cd. На Ubuntu отдельно устанавливается Chromium с системными зависимостями. Задание выполняет весь pytest и сохраняет агрегированные XML/JSON на семь дней. У него право contents: read. В артефакты не включаются исходники с настройками, HTML-копии исходников, браузерные профили и SQLite.

Проверка Git охватывает отслеживаемые файлы и текущих кандидатов на добавление. Проверены игнорирование окружений, файлов SQLite с журналами, локальных .env, ключей PEM, кешей и результатов тестов. Поиск известных форматов токенов и ключей в текущем дереве выявил уже отслеживаемую константу Django; проверка по шаблонам не гарантирует распознавания произвольного секрета. Производственная конфигурация и история удалённого Git не проверялись.
