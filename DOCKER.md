# Запуск в Docker на Mac

Это локальный запуск приложения через Gunicorn с DEBUG=false. Публикация на VPS
и HTTPS настраиваются отдельным этапом; порт открыт только на самом компьютере.

Из папки проекта при запущенном Docker Desktop:

```bash
python scripts/init_env.py
docker compose up -d --build
docker compose ps
docker compose logs --tail=100 web
```

Перед запуском остановите обычный runserver через Control+C, чтобы освободить
порт 8000. Откройте http://127.0.0.1:8000/ .

Скрипт создаёт случайный секрет в .env и не перезаписывает существующий файл.
Если .env уже есть, добавьте DJANGO_SECRET_KEY вручную. Django напрямую этот
файл не читает: переменные подставляет Compose. Ключ YANDEX_MAPS_API_KEY можно
добавить в .env; без него карта может быть недоступна.

Gunicorn исполняет Django, WhiteNoise отдаёт собранные CSS/JS. При запуске
контейнера применяются миграции. Приложение работает от пользователя app,
база хранится в volume quiet-queue_database, а не внутри удаляемого контейнера.

База контейнера новая, учреждения и аккаунты из обычного локального db.sqlite3
автоматически не переносятся. Создать администратора:

```bash
docker compose exec web python manage.py createsuperuser
```

Затем откройте http://127.0.0.1:8000/admin/ и добавьте учреждения.

Проверить сохранение данных:

```bash
docker compose down
docker compose up -d
```

После этого созданный администратор и учреждения должны остаться. Флаг -v
у команды down удаляет volume вместе с базой; для обычной остановки он не нужен.
Volume сохраняет базу между перезапусками, но не заменяет резервную копию.

Проверка состояния приложения:

```bash
curl --fail http://127.0.0.1:8000/healthz/
```

Healthcheck проверяет соединение с SQLite, а не все пользовательские сценарии.
Docker отмечает контейнер unhealthy при сбое проверки; политика restart
перезапускает завершившийся процесс, но не просто unhealthy-контейнер.

## Автоматическая проверка

CI запускает Django checks, миграции, сбор статики и семь тестов. После них
отдельный job docker собирает образ, поднимает Compose, проверяет healthz,
главную страницу и непустой CSS, а затем пересоздаёт контейнер и проверяет
сохранение контрольной записи в SQLite. При провале проверки job становится
красным. Эти данные создаются только в изолированной базе GitHub runner.
