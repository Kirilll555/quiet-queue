## Frontend и пользовательские сценарии

Проверены клавиатурное закрытие меню и фокус, сохранение режима чтения, пустая поисковая выдача, заполнение зависимого списка кабинетов, отправка форм и выход. Пиксельное сравнение, работа со скринридером, Safari, Firefox и интеграция с действующим ключом Яндекса остаются за пределами проверенного. ## Нагрузка и сохранность данных

Четыре независимых потока отправили 48 HTTP GET на тестовый Django-сервер с 20 учреждениями. Проверены конечный URL, код ответа, содержимое и число карточек всех 48 страниц. В полном прогоне серия заняла 0,086 с, скорость составила 559,6 запр/с, p95 — 10,4 мс. Время отдельного запроса включало чтение ответа. Значения характеризуют короткий прогон на loopback с временной файловой SQLite и инструментированием покрытия. Отдельный тест двух одновременных POST проверил отсутствие дубликатов.

У рабочей db.sqlite3 до и после прогонов совпала контрольная сумма SHA-1 `8a2cd6fb52b8b7cf4db3a133367dfa7d03429f61`. Для тестов использовалась база в отдельном временном каталоге со схемой всех шести миграций pages.

## Результат углублённого аудита

Проверены утверждения по всем тестовым функциям, включая параметризации, и причины всех ожидаемых падений. Шесть прежних xfail по четырём дефектам сохранились. Седьмой соответствует подтверждённому дефекту прав модерации BUG-05. Проверки известных сбоев используют strict=True и ограничение конкретной причины ошибки. Реестр выводов и границ интерпретации приведён в [аудите тестов](TEST_AUDIT.md), дефекты — в [BUG_REPORT.md](BUG_REPORT.md).

Перед полным прогоном нагрузка и конкурентная отправка прошли в трёх независимых запусках. На 48 GET в каждой серии получены 445,8 / 496,4 / 432,0 запросов в секунду и p95 24,8 / 19,3 / 18,2 мс. Это наблюдения на локальной машине без установленного SLO.

При первой диагностической попытке сборщик V8 ожидал ответ профилировщика во время перехвата навигации. Этот прогон был остановлен. В окончательной реализации замеры делаются на загруженных страницах и перед закрытием вкладки. В полном прогоне V8 зарегистрировал вызовы 10/10 наблюдаемых функций catalog-map.js, 6/6 navigation.js, 4/4 rate.js и 3/3 reading-mode.js. Итого 23/23, включая верхнеуровневые функции скриптов. JSON доступен в [отчёте JavaScript](qa-results/javascript.json). Пропущенные пути внутри вызванной функции эта метрика не выявляет.

Ветка qa содержит новый локальный workflow, подготовленный с учётом конфигурации из origin/devops-ci-cd. YAML разобран локально, браузерный набор и формирование артефактов проверены на macOS. Выполнения в GitHub Actions или Linux в рамках аудита не было. Изменений в pages/, config/, static/, manage.py и requirements.txt относительно e27eead нет.

## Финальная готовность

Добавлены только короткие проверки недостающих границ: симметричные пределы координат, значение choices модели, отсутствие полного прогнозного часа, HEAD публичных страниц, 404 неизвестного URL и базовые доступные имена интерфейса. QA-зависимости больше не переопределяют Django: workflow сначала устанавливает командный requirements.txt, затем инструменты из requirements-test.txt. Локальный финальный прогон выполнен на имеющемся Django 6.1.3; командный pin Django 6.1.1 будет проверен workflow на Ubuntu после публикации ветки.
