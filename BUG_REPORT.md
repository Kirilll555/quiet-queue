# Открытые дефекты

Ветка `qa`, исходный коммит `e27eead`. Все пять дефектов подтверждены на Django 6.1.3 и SQLite. Для воспроизведения отдельного случая используйте `.venv/bin/python -m pytest -k ИМЯ_ТЕСТА --runxfail --no-cov -v`. Набор использует временные данные.

| ID | Влияние | Шаги | Ожидание | Фактический результат | Имя теста |
|---|---|---|---|---|---|
| BUG-01 | Разработчик не может запустить объявленную команду | В тестовом окружении вызвать через Django команду seed_data | Обнаруженная команда создаёт экземпляр Command и выполняется | AttributeError при обращении к module.Command. Файл команды пуст | test_seed_command |
| BUG-02 | В очереди модерации появляются данные, нарушающие ограничения модели | Передать в POST формы предложения название из 256 символов и допустимую категорию. Во втором примере передать допустимое название и категорию из 101 символа | Сервер отклоняет заявку, превышающую предел 255 или 100 соответственно | В обоих примерах появляется строка InstitutionRequest. Представление проверяет только наличие непустых значений | test_suggestion_respects_model_lengths |
| BUG-03 | Посетитель пропускает учреждение при поиске | Создать учреждение «Центр». Искать «центр» в каталоге | Поиск по названию через icontains находит учреждение | В используемой SQLite выборка пуста при смене регистра кириллицы | test_catalog_cyrillic_case |
| BUG-04 | Опубликованное учреждение нельзя выбрать по его типу из фильтра | Добавить учреждение типа «Почта» или «Другое». Открыть фильтр каталога | Опубликованный тип, доступный при подаче заявки, доступен для выбора | В списке есть только «Все», «Поликлиники» и «МФЦ» | test_catalog_filter_offers_published_type |
| BUG-05 | Сотрудник с единственным правом просмотра заявок может публиковать учреждения | Проверить доступные действия в списке заявок для сотрудника с правом просмотра | Публикация требует полномочий на изменение заявки и добавление учреждения | Роль просмотра видит действие одобрения. В изолированной QA-базе при аудите подтвердились изменение статуса и публикация. Форма ручного создания для той же роли возвращает 403 | test_read_only_staff_cannot_moderate |

Проверки задают ожидаемое поведение. Метка xfail(strict=True) отделяет известные сбои в обычном прогоне и сигнализирует об изменении поведения при исправлении. Повторный диагностический прогон с --runxfail дал 7 падений по указанным причинам.

Для BUG-05 приоритет высокий. При исправлении следует проверить полномочия на серверной стороне и ограничить доступность действия в интерфейсе. Постоянный регрессионный тест проверяет опубликованный список действий; изменение состояния было отдельно проверено в ходе аудита.

### Наблюдение по конфигурации

В исходном отслеживаемом config/settings.py обнаружены фиксированный SECRET_KEY и DEBUG=True. Для учебной локальной конфигурации это отдельное наблюдение. Использование данного ключа в развёрнутой среде не проверялось. Значение в отчётах не приводится. Для развёртывания нужны отдельная конфигурация и собственный ключ.
