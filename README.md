# Тихая очередь (Quiet Queue)

Учебный проект по дисциплине «Обучение служением», МАИ.

Сервис помогает посмотреть загруженность общественных учреждений и выбрать время планового посещения по оценкам посетителей.

Демонстрационные учреждения, координаты и отметки не отражают реальную ситуацию.

## Возможности

- Каталог учреждений с поиском и фильтром по типу.
- Просмотр учреждений списком и на Яндекс Картах.
- Отдельные статусы общей очереди и очередей кабинетов.
- Регистрация по нику и паролю, вход и выход.
- Отправка отметок после авторизации.
- Ограничение повторных отметок в одну очередь.
- Предложение учреждений с модерацией через админку.
- Статистический прогноз загруженности по истории оценок.

## Технологии

Python, Django, SQLite, Django Templates, HTML, CSS, JavaScript, JavaScript API Яндекс Карт 2.1.

Локально проект запускался на Python 3.14.7 и Django 6.1.3.

## Первый запуск в Windows PowerShell

### 1. Получение проекта

Для новой локальной копии:

```powershell
git clone --branch frontend https://github.com/Kirilll555/quiet-queue.git
cd quiet-queue
```

Если репозиторий уже есть на компьютере, повторно клонировать его не нужно.

### 2. Виртуальное окружение

```powershell
py -m venv .venv
```

Активация окружения не обязательна: следующие команды используют его Python напрямую.

### 3. Установка Django

```powershell
.\.venv\Scripts\python.exe -m pip install --upgrade pip
.\.venv\Scripts\python.exe -m pip install "Django==6.1.3"
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

### 4. Подготовка базы

```powershell
.\.venv\Scripts\python.exe manage.py migrate
.\.venv\Scripts\python.exe manage.py check
```

Миграции создают структуру базы. Учреждения, кабинеты и история оценок автоматически не заполняются.

### 5. Настройка Яндекс Карт

Получите ключ JavaScript API в кабинете разработчика Яндекс.

В том же PowerShell, где будет запущен сервер:

```powershell
$env:YANDEX_MAPS_API_KEY = "ВАШ_КЛЮЧ"
```

Ключ не следует записывать в исходный код или коммитить в репозиторий.

Настройка действует только в текущем окне PowerShell. После его закрытия её нужно задать заново. При размещении сервиса переменную окружения настраивает DevOps.

JavaScript API использует браузерный ключ, поэтому посетитель может увидеть его в запросах страницы. Ограничения ключа задаются в кабинете Яндекс.

Карта требует подключения к интернету. При отсутствии ключа список учреждений остаётся доступным.

### 6. Запуск

```powershell
.\.venv\Scripts\python.exe manage.py runserver
```

Сайт: http://127.0.0.1:8000/

Оставляйте терминал открытым, пока работаете с сайтом. Остановка сервера — Ctrl+C.

`runserver` предназначен для локальной разработки. Публичное размещение настраивается отдельно.

## Повторный запуск после выключения компьютера

Перейдите в свою папку репозитория, затем выполните:

```powershell
$env:YANDEX_MAPS_API_KEY = "ВАШ_КЛЮЧ"
.\.venv\Scripts\python.exe manage.py runserver
```

Если получили изменения команды с новыми миграциями, перед запуском выполните:

```powershell
.\.venv\Scripts\python.exe manage.py migrate
```

## Учреждения, кабинеты и модерация

Создайте локального администратора:

```powershell
.\.venv\Scripts\python.exe manage.py createsuperuser
```

Админка: http://127.0.0.1:8000/admin/

Через админку можно:

- создавать учреждения, заполнять адреса и часы работы;
- указывать широту и долготу для отображения на карте;
- добавлять кабинеты и связывать их с учреждениями;
- просматривать отметки;
- одобрять заявки действием «Одобрить выбранные заявки и добавить на сайт».

Учреждение без координат отображается только списком. Для карты должны быть заполнены обе координаты.

После одобрения заявки проверьте адрес, график, координаты и кабинеты созданного учреждения.

Для демонстрационных данных используйте явно обозначенные учебные названия и условные координаты.

## Аккаунты и отметки

Для регистрации запрашиваются ник и пароль с подтверждением. ФИО, телефон и email в форме регистрации не запрашиваются.

Используйте вымышленный ник. Самостоятельное восстановление пароля через email или телефон пока не реализовано.

Просмотр каталога и прогноза доступен без входа. Отправка отметки требует авторизации.

Один аккаунт может оценивать одну очередь не чаще раза в 15 минут. Общая очередь учреждения и каждый кабинет учитываются отдельно.

Регистрация не подтверждает уникальность человека и не исключает создание нескольких аккаунтов.

## Расчёт текущего статуса

Учитываются отметки за последние 60 минут.

Для каждой очереди берётся последняя оценка каждого аккаунта:

- небольшая очередь — 1 балл;
- умеренная очередь — 2 балла;
- много людей — 3 балла.

Статус определяется по среднему:

- меньше 1,5 — небольшая очередь;
- от 1,5 до значения меньше 2,5 — умеренная очередь;
- от 2,5 — много людей.

Если свежих оценок нет, показывается «Нет свежих отметок».

Счётчик показывает количество учтённых аккаунтов для конкретной очереди за час. Старые отметки без автора в этот расчёт не входят.

Индекс загруженности не является числом людей или временем ожидания в минутах.

## Статистический прогноз

Прогноз анализирует историю выбранной очереди для того же дня недели и часа.

От каждого аккаунта учитывается одна последняя оценка за каждый исторический час.

Для оценки интервала требуются:

- минимум 3 разные исторические даты;
- минимум 5 учтённых оценок.

Рекомендуется интервал с наименьшим средним баллом среди обеспеченных данными. При равных баллах выбирается более ранний.

При нехватке истории показывается «Недостаточно данных». Отсутствие данных не означает отсутствие очереди.

Текущая реализация — статистический алгоритм, а не нейросеть. Качество прогноза на реальных данных пока не подтверждено.

Поддерживается ежедневный график вида `08:00–18:00`, включая вариант `08:00 - 18:00`. Анализируются полные часовые интервалы. Прошедшие интервалы сегодняшнего дня исключаются.

Выходные, праздники, перерывы и различающееся по дням расписание пока автоматически не учитываются.

Рекомендации предназначены только для плановых посещений. При необходимости срочной медицинской помощи нельзя откладывать обращение ради меньшей очереди. Время назначенного приёма следует согласовывать с учреждением.

## Структура интерфейса

Шаблоны: `pages/templates/`.

Стили: `static/css/`.

- `base_styles.css` — общие элементы, меню и футер.
- `index_styles.css` — каталог, карточки и карта.
- `rate_styles.css` — отправка отметок.
- `suggest_styles.css` — предложение учреждения.
- `auth_styles.css` — регистрация и вход.
- `ai_styles.css` — статистический прогноз.

JavaScript: `static/js/`.

- `rate.js` — обновление кабинетов в формах оценки и прогноза.
- `catalog-map.js` — Яндекс Карты и переключение представления.

## Работа с Git

Frontend-разработка ведётся в ветке `frontend`. Завершённые этапы интегрируются в `development`. Изменения команды получаем из `development`.

Перед объединением изменений сохраните свою работу коммитом и выполните `git fetch origin`.

Не используйте принудительный push в общую ветку.

Миграции включаются в коммиты. Локальная база `db.sqlite3`, виртуальное окружение и ключи API в репозиторий не отправляются.

Уже применённые миграции не переписываются: изменения структуры оформляются новыми миграциями.

## Проверки и работа QA

Проверка конфигурации:

```powershell
.\.venv\Scripts\python.exe manage.py check
```

Запуск автотестов:

```powershell
.\.venv\Scripts\python.exe manage.py test
```

Автотесты разрабатывает QA в `pages/tests/`.

Приоритетные сценарии:

- регистрация, вход, выход и возврат к форме после входа;
- запрет отправки отметки без авторизации;
- принадлежность кабинета учреждению;
- ограничение повторов, включая одновременные запросы;
- средний статус и исключение устаревших оценок;
- разделение очередей учреждения и кабинетов;
- прогноз при достаточной и недостаточной истории;
- поиск, фильтры, карта и модерация;
- отображение на узком экране и работа с клавиатуры.

## Если сайт не открывается

`ERR_CONNECTION_REFUSED` обычно означает, что локальный сервер не запущен или завершился с ошибкой. Проверьте терминал с `runserver`.

При ошибке `no such table` сначала проверьте:

```powershell
.\.venv\Scripts\python.exe manage.py showmigrations pages
.\.venv\Scripts\python.exe manage.py migrate
```

Если миграции считаются применёнными, а таблицы нет, сохраните резервную копию базы и разберите расхождение с backend. Не удаляйте базу и не применяйте `--fake` вслепую.

Если новые стили не появились, сохраните файл и обновите страницу через Ctrl+F5.
